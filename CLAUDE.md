# Erpeg: notes for Claude

- The owner does not program. They describe features in Polish; reply in Polish, avoid jargon, and verify changes yourself (build plus a Playwright screenshot/check) before reporting.
- Stack: Phaser 4 + TypeScript + Vite. `npm run build` runs a typecheck and the build. The Phaser 4 API differs from v3 (e.g. `setTintMode` instead of `setTintFill`); the bundled guides live in `node_modules/phaser/skills/`.
- The game is played on the real map of Lublin. `data/lublin-osm.geojsonseq.gz` is an OpenStreetMap extract made by `scripts/fetch-osm.sh`. Refresh it with the "Fetch Lublin map data" workflow (workflow_dispatch); the sandbox cannot reach OSM servers. `scripts/build-map.mjs` turns it into `public/map/lublin.json` (gitignored) before dev/build.
- Layout: `src/content/fabula.ts` holds the missions and enemy spots, written in Polish by address; the owner dictates these. `src/map/CityMap.ts` handles collisions, address lookup and spawn. `src/map/MapRenderer.ts` draws the map in chunks. `src/quests.ts` holds mission progress (localStorage). `src/art.ts` holds the placeholder sprites. `src/objects/` holds the player and enemies (plain sprites with `vel`, moved by GameScene with map collisions). `src/scenes/` holds Boot (loads the map), Game and UI (HUD, dialogs, goal arrow, touch controls).
- When adding missions, check that the addresses exist in the map data (the game also shows a toast listing any it cannot find).
- Mobile first: integer camera zoom. All input (touch, keyboard, mouse click) is handled natively in `src/controls.ts`; Phaser input for touch and keyboard is disabled because its pointer and key state got stuck on real devices. UIScene only draws the controls. Test at phone viewport too.
- `window.__game` is exposed for debugging and automated browser checks.
