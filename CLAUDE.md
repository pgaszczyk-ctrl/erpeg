# Exp-lore (formerly Erpeg): notes for Claude

- The game's name is Exp-lore (a placeholder); the menu shows it as a pixel logo (`src/ui/logo.ts` `pixelLogo`, GAME_NAME). Address: https://exp-lore.app (the owner's Cloudflare domain, GitHub Pages custom domain); the old github.io address redirects there.

- The owner does not program. They describe features in Polish; reply in Polish, avoid jargon, and verify changes yourself (build plus a Playwright screenshot/check) before reporting.
- Stack: Phaser 4 + TypeScript + Vite. `npm run build` runs a typecheck and the build. The Phaser 4 API differs from v3 (e.g. `setTintMode` instead of `setTintFill`); the bundled guides live in `node_modules/phaser/skills/`.
- The game is played on the real map of Lublin. `data/lublin-osm.geojsonseq.gz` is an OpenStreetMap extract made by `scripts/fetch-osm.sh`. Refresh it with the "Fetch Lublin map data" workflow (workflow_dispatch); the sandbox cannot reach OSM servers. `scripts/build-map.mjs` turns it into `public/map/lublin.json` (gitignored) before dev/build.
- Layout: `src/content/fabula.ts` holds the missions and enemy spots, written in Polish by address; the owner dictates these. `src/map/CityMap.ts` handles collisions, address lookup and spawn. `src/map/MapRenderer.ts` draws the map in chunks. `src/quests.ts` holds the logged-in session and mission progress. `src/api.ts` talks to the server. `src/ui/menu.ts` is the HTML start screen (new character, load, memorial). `src/art.ts` holds the placeholder sprites. `src/objects/` holds the player and enemies (plain sprites with `vel`, moved by GameScene with map collisions). `src/scenes/` holds Boot (loads the map), Game and UI (HUD, dialogs, goal arrow, touch controls).
- When adding missions, check that the addresses exist in the map data (the game also shows a toast listing any it cannot find).
- Mobile first: integer camera zoom. All input (touch, keyboard, mouse click) is handled natively in `src/controls.ts`; Phaser input for touch and keyboard is disabled because its pointer and key state got stuck on real devices. UIScene only draws the controls. Test at phone viewport too.
- Scale: `PX_PER_M` (1.92) in CityMap. Stored positions carry their scale (players.map_scale, snapshot `s`, fog `s`) and are converted on load.
- Fog of war: `src/map/Fog.ts`. Vision is a raycast cone blocked by buildings. Explored cells are saved in the save as `fog`. Enemies and pickups outside the vision are hidden. The map screen is `src/ui/minimap.ts` (🗺 button or M).
- Shops (every OSM shop=supermarket/discount whatever the chain, so it works abroad too; in towns also named convenience shops) and schools come from OSM POIs (`pois` in the map JSON, `CityMap.places`). Shops sell swords; prices and stats live in `src/content/sklepy.ts`. Schools give quizzes instead of sword lessons (`openSchool`, SZKOLA_QUIZ in `src/content/quizy.ts`: 50 a day per school (never shown to the player) in `session.daily['szkola:<id>']` (a = answered, n = break end in minutes after midnight), lessons of `naLekcje` 10 then a break until now + `przerwaMin` 3 min rounded up to :x0/:x5, 10 EXP each (a wizard also gets `magia` practice), one level harder from the 31st and two from the 41st (`trudniejOd`), no repeats within a school day; `src/quizzes.ts` `schoolQuiz` picks today's server questions (table `quizzes`, RPC `school_quizzes` loaded in loadContent), the built-in QUIZY or a made-up number puzzle, by the player's level). An outside program uploads questions with RPC `add_quizzes(p_key, p_quizzes, p_days=2)` (key: admin panel → Ustawienia → quiz card, `admin_new_quiz_key`, bcrypt in admin_config `quiz_key`); each batch is valid 2 days, expired rows are deleted on upload; `quiz_history` (normalised question text) rejects repeats forever (`_insert_quizzes`, shared by add_quizzes and the daily Claude routine "Quizy do szkół (Erpeg)", 2:45 Warsaw, fires into the Claude session that holds the Supabase connector). See docs/quizy.md. Sword and skill are stored in the save. Entering a shop or school is a save point too. Separate sidewalk/crossing ways are dropped in build-map; car roads are drawn with a stone sidewalk edge.
- Churches, offices and police stations give random missions (`src/content/zlecenia.ts`, `missionForPlace` in quests.ts). The seed is place id + a per-login nonce, so each login brings a new one. Taken, unfinished ones are kept in the save as `gen`. Police gives bounties: a bandit hidden near a spot (`szukaj`: the arrow shows only the area) or a big slime. Hospitals heal for free. Enemy kinds are in `ENEMY_KINDS` (objects/Slime.ts).
- Map look: build-map drops roofs/shelters and tiny buildings (<25 m² without address), grows every building by 0.7 m, merges touching ones and cuts every road out as wide as it is drawn (clipper-lib, ~5 min; skipped when the JSON is newer than the data and the script). All roads, pavements and paths are drawn as one track: every outline first, then every fill in one colour.
- `src/scenes/Ambient.ts`: fruit trees on green areas (deterministic per area, created near the hero; swinging drops one fruit, 2–5 per tree, regrow each login; fruit sold in shops, prices in content/sklepy.ts) and monster gangs (`StreetEnemies`, params in `src/content/gangi.ts`): enemies no longer roam the streets; they sit in gang territories (Banda: 110 m, 4–6 members; small: 220 m, 6–9; big: 450 m, 12–18) planned per 1 km cell (seeded by map + login nonce, density × `potwory` × night, ×2 in cells with under 3 places – villages and fields, GANG_WIES – and centres mostly within 150 m of a road), centres ≥ GANG_OD_MIEJSC_M from places/home, members away from doors. A light red mist (GANG_MGLA) covers the territory, with sparse red one-pixel flies buzzing only inside it (GANG_MUSZKI, `drawFlies`: fixed grid spots in view, redrawn every frame); no townsfolk/riddle-givers/fixed NPCs/sports people are shown inside until it has been cleared for GANG_POWROT_S (60 s). Members never leave the territory: `Slime.leash` makes them give up the chase once the hero (or they) are past the border. When every member is dead the boss (`herszt`/`wielki_herszt`) comes out at the centre; killing him clears the gang (reward coins+EXP, `stats.gangs`).
- Headless Chromium frame times vary a lot between containers; compare against an older build on the same machine before calling something a regression.
- Items and skills: `src/content/przedmioty.ts` (catalogue: weapon in hand, ranged bow or magic item, armour, helmet, boots; skill curve 100 × 1.5^n up to level 10). `src/inventory.ts` holds `gear`: equip, a 5-slot bag (fruit stacks to 99), skill practice points and the magic flag. Saved as equip/bag/skills/magic; old sword/swordSkill/fruits saves are converted in loadGear. A tap is a melee swing; holding over 250 ms (or dragging) aims and releasing shoots (`hold`/`consumeRelease` in controls.ts, `updateRanged`/`updateShots` in GameScene). Hits on enemies, trees and training stations (dummy/target/crystal on sports pitches, `Training` in Ambient.ts) give practice. Libraries teach magic and sell magic items; schools sell lessons (+practice). Character sheet: `src/ui/character.ts` (👤 or C).
- Admin panel: `admin.html` + `src/admin/admin.ts` (no Phaser). Auth: admin password checked by `_admin_ok` (bcrypt in `admin_config`, 5 bad tries lock 10 min); RPCs `admin_overview`, `admin_save_mission`, `admin_save_code`, `admin_set_key`. Missions made there live in table `missions` (same fields as `Misja`), are loaded at login by `game_content` (`loadContent` in quests.ts, 5 s timeout) and merged with MISJE. Zadanie typ `brak` = just a place.
- Secret codes: table `secret_codes` (code, mission_id, reward item, max_uses) + `redemptions` (once per character). In a mission dialog whose id has an active code the game adds "🤫 Psst, mam tajemne hasło" (`missionDialog`/`tellSecret` in GameScene, prompt in `src/ui/prompt.ts`), RPC `redeem_code` (10 bad tries per hour). Mythic items in przedmioty.ts have `efekt`: `swiatlo` (vision ×SWIATLO, glow) and `pioruny` (auto lightning, PIORUNY).
- Death and resurrection: `die` stores death_x/y/scale and stats and adds a row to `deaths` (the memorial board reads `deaths`). The start screen shows a dead character's ghost on a still map (`ghostMap` in menu.ts, `drawCity` in `src/map/drawCity.ts`). `resurrect` is free the first time; later ones answer "1 €, payments soon".
- Stats in the save (`stats`: m walked, kills per kind, earned, spent, fruit, missions, codes), counted via `earn`/`spend` in quests.ts. Eating 20 fruit heals one heart (character sheet). Practice hits show a skill bar (UIScene `showPractice`: icon + framed yellow bar, no blur – the soft blurred one was invisible on the map).
- Home: a house at the start point (TEX.home). Coming back to it heals fully, saves and offers the chest (`src/ui/chest.ts`): 10×10 slots + money, saved as `chest` {slots, coins}; drag with pointer events or tap to move between chest and backpack.
- Riddle-givers ("mądrale", `src/scenes/Npcs.ts`; names in `src/content/zagadki.ts` MADRALE with `k` = woman): they ask requests "from life" (`requestFor`, texts in `src/content/prosby.ts`: kitchen, pets, weather, first aid, plus made-up ones from today's date/clock/where they stand: day of the week, in N days, days until, time left to an appointment, distance to a town rounded to 20 km (straight line × DROGA_RAZY), shopping sums); a request key is not asked again within NIE_POWTARZAJ_DNI (60) days (`session.seen`, saved as `seen`); reward 5 coins or 2 apples + EXP by level. Old description: every day about one in 4 schools/churches gets one on a street ~500 m away (seeded by date). One riddle a day each, one try, picked for the player's age (players.age, asked at creation, default 7) and the NPC's difficulty (−1/0/+1 level); half are generated sums. Answers kept in the save as `riddles` {npcId: day}.
- Languages: `src/i18n.ts` picks Polish or English from the device (`?lang=pl|en` forces it); two-language texts are `{ pl, en }` read with `tr()`, or inline `tx(pl, en)`. So far only the fixed characters are bilingual; the rest of the game is still Polish.

- Map streaming (Lublin): build-maps writes the whole map to `.cache/lublin-full.json` (not published), then `scripts/split-map.mjs` (runs the game's own CityMap in Node with --experimental-strip-types) cuts it into an index `public/map/lublin.json` (boundary, paved/big areas, `bld` = every building with an address or name as a stub with bbox + precomputed door, `places`, `streets` = start point per street name) and 1 km tiles `public/map/lublin/<cx>_<cy>.json` (areas/lines/buildings with their full-map `id`; a feature is in every tile it touches, deduped by id on load). CityMap tile mode: `ensure(x, y, r)` fetches tiles, `ready(box)`, `onTile` (MapRenderer redraws those chunks in place), unloaded tiles are blocked in `isBlocked`, stubs get their rings when their tile arrives (same object, so place.building identity holds), `addressed()` for random mission targets, seeds/draw order use `id`. Loading: `prepareMap` (travel.ts) before a scene starts (1 km around arrival/home/unfinished-session spot, 400 m around fixed characters' streets), GameScene.update keeps `LOAD_RADIUS` (2 km) loaded; per-cell caches (Townsfolk, StreetEnemies, Forest) skip cells that aren't `ready`; minimap, ghost map, admin preview and the dragon spot fetch what they need first. Towns stay single files.
- The Lublin map is the city boundary plus 8 km circles around Motycz-Józefin, Jastków, Garbów and Nałęczów (`scripts/lublin-area.json`, union in build-map `withCircles`; fetch-osm.sh BBOX covers them), so they are reachable on foot along every real road.
